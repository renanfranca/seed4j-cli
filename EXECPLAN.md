## Decisions

The packaged configuration scenario exposed a CLI launcher defect: `JavaProcessChildLauncher` dropped `user.home` when starting the standard child JVM. Preserve the explicit `Seed4JCliHome` from the pre-Spring composition root in that child command. A diagnostic comparison using the prior JAR showed the normal launch ignored the config while a direct child launch applied it. Changing only the test environment with `JAVA_TOOL_OPTIONS` would mask the runtime inconsistency; forwarding the existing home preserves the configuration contract and makes the isolated acceptance proof valid. No engine-specific initialization is added. The packaged regression and existing command expectations cover this correction; undoing it would invalidate the isolated-home evidence.
